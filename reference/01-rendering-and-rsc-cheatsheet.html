Rendering Engines & RSC Architecture

Bảng tra cứu nhanh cú pháp, quy tắc ranh giới Server/Client và tư duy kiến trúc trả lời phỏng vấn.

1. Server vs Client Boundaries

  • Server Component (Mặc định): 0KB Client JS, fetch DB trực tiếp, giữ Secrets an toàn.
  • Client Component (`'use client'`): Dùng cho Hooks (`useState`, `useEffect`), Event Listeners (`onClick`), Browser APIs.
  • Serialization Boundary: Props truyền qua ranh giới phải serialize được (No Functions, No Classes).
  • Slot Pattern: Truyền Server Component dạng children prop vào Client Component để giữ nguyên trạng thái Server.

2. Dynamic Functions (Trigger Dynamic SSR)

  • cookies() từ next/headers
  • headers() từ next/headers
  • Prop searchParams trong page.tsx
  • fetch(url, { cache: 'no-store' }) hoặc revalidate: 0

3. Revalidation & ISR Syntax

  • export const revalidate = 60; (Time-based ISR)
  • fetch(url, { next: { tags: ['posts'] } }) (Tag-based)
  • revalidateTag('posts') (On-Demand từ Server Action)
  • revalidatePath('/blog') (Clear cache theo URL)

4. Streaming & PPR (Next.js 15)

  • loading.tsx: Tự động bọc Suspense fallback quanh page.tsx.
  • <Suspense fallback={...}>: Granular Streaming từng phần.
  • Promise.all([p1, p2]): Triệt tiêu nghẽn Waterfall Fetch.
  • PPR (Partial Prerendering): Static Shell (CDN 0ms) + Dynamic Holes (Streamed).

Bí Quyết Trả Lời Phỏng Vấn (Senior Cheat-Sheet)

🎯 3 Câu hỏi "Bẫy" hay gặp nhất:

1. "Client Component có phải chỉ render ở Browser không?"
-> Trả lời: KHÔNG! Client Component vẫn được pre-render thành HTML ở Server (SSR), sau đó Hydrate ở Browser.

2. "Làm sao tránh Waterfall Fetch?"
-> Trả lời: Dùng Promise.all() để fetch song song hoặc tách nhỏ component lồng <Suspense>.

3. "Stale-While-Revalidate của ISR hoạt động ra sao khi cache hết hạn?"
-> Trả lời: Trả về dữ liệu cũ (Stale) lập tức cho user đầu tiên, kích hoạt Background Rebuild, user sau nhận dữ liệu mới.
