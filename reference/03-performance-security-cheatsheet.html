Performance Optimizations & Security Architecture

Bảng tra cứu nhanh về Hydration Mismatch, Core Web Vitals, Auth Sessions và Secrets Protection.

1. Hydration Mismatch Solutions

  • Nguyên nhân: `new Date()`, `Math.random()`, window/localStorage ở render phase, lồng HTML sai quy chuẩn.
  • Fix 1 (Side-effects): Đưa logic đọc Date/Storage vào `useEffect()`.
  • Fix 2 (Attribute): Dùng `suppressHydrationWarning` cho 1 tag cụ thể.
  • Fix 3 (Dynamic): `dynamic(() => import(...), { ssr: false })` ngắt SSR.

2. Core Web Vitals Targets

  • LCP (< 2.5s): Preload LCP image với `priority`, dùng Streaming SSR Static Shell.
  • INP (< 200ms): Thay thế FID cũ, cắt giảm Long Tasks Main Thread, dùng `useTransition`.
  • CLS (< 0.1): Cố định width/height ảnh, dùng `next/font` (display: swap).
  • Measurement: Tích hợp `useReportWebVitals` hook.

3. Auth & Session Architecture

  • HttpOnly Cookie: Chuẩn an toàn duy nhất cho SSR/RSC (chống XSS, tự động đính kèm request).
  • Auth.js v5: Lấy session ở Server Component qua `await auth()`.
  • Middleware Wall: Filter cookie tồn tại sơ bộ ở Edge CDN.
  • Page Level RBAC: Check quyền chi tiết tại Server Component / Database level.

4. Security & Secrets Protection

  • `import 'server-only'`: Đặt ở đầu file secret để báo lỗi Build Error nếu nhầm sang Client Component.
  • Env Variables: `NEXT_PUBLIC_` nạp vào Client bundle; không có tiền tố CHỈ tồn tại ở Server.
  • CSRF Protection: Server Actions tự kiểm tra Host & Origin headers.

Bí Quyết Phỏng Vấn (Senior Cheat-Sheet)

🎯 3 Câu hỏi "Xương Sẩu" trong phỏng vấn:

1. "Tại sao không lưu JWT vào LocalStorage?" -> XSS trộm được token và Server Component không đọc được LocalStorage.

2. "Vì sao Google bỏ FID thay bằng INP?" -> FID chỉ đo tương tác đầu tiên; INP đo độ trễ của MỌI tương tác trên trang.

3. "Làm sao đảm bảo 100% không rò rỉ DB Secret Key xuống Client?" -> Dùng package server-only ở đầu file secret và không gắn tiền tố NEXT_PUBLIC_.
